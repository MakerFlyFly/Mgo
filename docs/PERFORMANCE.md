# 流式与按需连接的耗时对比

2026-10-17，Asia/Kuala_Lumpur。基线为 `f18d08e`，新版为本次流式实现。两版均使用本机 Docker 生产镜像、个人模式、同一 DeepSeek 模型及账号；每个场景分别新建会话、连续测三次。查店只读取上海人民广场附近餐厅，不选择门店、不创建订单。

| 场景 | 旧版首字中位数 | 新版首字中位数 | 旧版总耗时中位数 | 新版总耗时中位数 |
|---|---:|---:|---:|---:|
| 一句闲聊问候 | 17.081 秒 | 0.954 秒 | 17.082 秒 | 1.432 秒 |
| 查询附近自取餐厅 | 18.449 秒 | 1.788 秒 | 18.449 秒 | 5.442 秒 |

首字指收到首个非空 `utterance_delta` 的时间；旧版以完整 `reply` 到达为准。总耗时包含最终台词和 `done`。这是三次小样本实测，网络、模型排队及缓存都会影响结果，不代表固定响应时限。

新版三次闲聊均只有一次模型请求，MCP 初始化次数为零。三次查店均先产生过程台词，再执行实际查询；首个查店请求含冷连接，后续在 60 秒内复用连接。模型遗漏过程台词时，程序先返回执行顺序提示，让 Agent 补齐台词后才真正查询；纠正请求也计入模型和工具上限。

完整逐次数据及仅含标识、工具名称和耗时的服务端记录见 [streaming-comparison.json](performance/streaming-comparison.json)。未保存对话正文、工具参数、个人信息或凭据。

复现：对旧版和新版分别启动独立的本地生产容器，然后运行：

```bash
node scripts/benchmark-chat.mjs http://127.0.0.1:3000 tmp/chat-benchmark.json 3
```

脚本读取本地 `.env.local`；个人模式使用服务端配置，模拟模式仅在请求内传递本地 DeepSeek Key。输出只包含场景名、首字/回复/总耗时及过程台词数量。默认两个场景都不会提交订单。
